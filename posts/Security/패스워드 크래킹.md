# 암호화와 해시

## 암호화

> 키 값을 이용하여 평문을 암호문으로 변환하는 과정

- 암호화에 사용된 키를 이용하여 원래 평문으로 복호화할 수 있음
- 데이터의 내용을 숨기는 것이 목적

```text
평문
 ↓ 암호화
암호문
 ↓ 복호화
평문
```

## 해시

> 임의의 입력 데이터를 해시 함수를 통해 고정된 길이의 해시값으로 변환하는 과정

- 해시는 암호화와 달리 원래 데이터를 다시 복원하는 것을 목적으로 하지 않음
- 해시값으로부터 원래 입력값을 직접 복원하는 것은 현실적으로 어려움
- 데이터 무결성 확인, 비밀번호 저장 등에 사용됨

```text
입력값
 ↓ Hash
해시값
```

---

# 해시 함수

- 임의의 길이의 입력을 받아 고정된 길이의 해시값을 출력하는 함수

```text
Hash(message) = hash value
```

- SHA-256은 입력 크기와 관계없이 256bit의 해시값을 출력
- SHA-512는 입력 크기와 관계없이 512bit의 해시값을 출력
- MD4, MD5, SHA-1 등은 충돌 공격에 대한 취약점이 발견되어 보안 목적으로는 사용하지 않는 것이 권장됨

## 해시 함수의 특징

### 1. 고정된 길이의 출력

입력 데이터의 크기가 달라도 출력되는 해시값의 길이는 일정함.

```text
"a"
 ↓ SHA-256
256bit

"hello world"
 ↓ SHA-256
256bit
```

### 2. 일방향성

해시값으로부터 원래 입력값을 직접 계산하는 것은 현실적으로 어려움.

```text
Password
   ↓ Hash
Hash Value
```

해시는 암호화처럼 복호화 키가 존재하지 않음.

### 3. 같은 입력은 같은 출력

같은 해시 함수에 같은 입력값을 넣으면 항상 같은 해시값이 출력됨.

```text
Hash("1234") = A
Hash("1234") = A
```

### 4. 충돌

서로 다른 입력값이 같은 해시값을 가지는 경우를 충돌(Collision)이라고 함.

```text
Hash(A) = X
Hash(B) = X
```

해시값의 출력 공간은 유한하지만 입력값의 경우의 수는 훨씬 크기 때문에 이론적으로 충돌은 발생할 수 있음.

안전한 해시 함수는 이러한 충돌을 현실적으로 찾기 어렵도록 설계되어야 함.

---

# 비밀번호와 해시

서버에서는 일반적으로 사용자의 비밀번호를 평문 그대로 저장하지 않고 해시값을 저장함.

```text
Password
   ↓ Hash
Hash Value
   ↓
DB에 저장
```

사용자가 로그인하면 입력한 비밀번호를 다시 해시하여 DB에 저장된 값과 비교함.

```text
사용자 입력 Password
        ↓ Hash
      Hash Value
        ↓
DB의 Hash Value와 비교
```

하지만 비밀번호를 단순히 해시해서 저장하면 같은 비밀번호를 사용하는 사용자는 같은 해시값을 가지게 됨.

```text
User A : password123
User B : password123
```

```text
Hash("password123") = X

User A → X
User B → X
```

이를 방지하기 위해 Salt를 사용함.

---

# Salt

> 비밀번호를 해시할 때 추가하는 임의의 값

- 일반적으로 사용자마다 서로 다른 Salt 값을 사용함
- Salt 자체는 비밀값일 필요는 없음
- 보통 Salt는 비밀번호 해시값과 함께 저장함

```text
User A
Password + Salt A
      ↓ Hash
   Hash A

User B
Password + Salt B
      ↓ Hash
   Hash B
```

같은 비밀번호라도 Salt가 다르면 서로 다른 해시값이 생성됨.

```text
Hash("password123" + "ABC")
        ≠
Hash("password123" + "XYZ")
```

예시:

```text
User | Salt | Password Hash
---------------------------
A    | ABC  | 8f21...
B    | XYZ  | ab91...
```

Salt를 사용하면 미리 계산된 해시값을 여러 사용자에게 그대로 재사용하기 어려워짐.

---

# 비밀번호 해시 공격

해시값 자체를 복호화할 수는 없지만 공격자는 가능한 비밀번호 후보를 직접 해시하여 비교할 수 있음.

예를 들어 공격자가 다음 해시값을 얻었다고 가정함.

```text
Target Hash = Hash("1234")
```

공격자는 여러 비밀번호 후보를 해시함.

```text
Hash("0000") → 비교
Hash("0001") → 비교
Hash("0002") → 비교
...
Hash("1234") → Target Hash와 일치
```

이 경우 원래 입력값이 `"1234"`일 가능성을 알아낼 수 있음.

즉 해시를 역산한 것이 아니라 가능한 입력값을 직접 해시하여 결과를 비교한 것임.

---

# Rainbow Table

비밀번호 후보를 공격할 때 매번 모든 비밀번호 후보를 해시하면 많은 계산 시간이 필요함.

이를 줄이기 위해 비밀번호와 해시값을 미리 계산하여 저장해둘 수 있음.

```text
password1 → hash1
password2 → hash2
password3 → hash3
...
```

하지만 가능한 모든 비밀번호와 해시값을 저장하면 매우 많은 저장 공간이 필요함.

Rainbow Table은 계산 시간과 저장 공간을 절충하는 Time-Memory Trade-Off 기법을 사용함.

---

# Reduction Function

Rainbow Table에서는 해시값을 다시 비밀번호 후보 공간의 값으로 변환하기 위해 Reduction Function을 사용함.

```text
Password
   ↓ Hash
Hash Value
   ↓ Reduction
새로운 Password Candidate
```

Reduction Function은 해시의 역함수가 아님.

```text
X : 해시를 복호화하는 함수

O : 해시값을 비밀번호 후보 공간의 값으로 매핑하는 함수
```

예를 들어:

```text
Hash("hello")
    ↓
abc1234f...

Reduction(abc1234f...)
    ↓
"test12"
```

Reduction의 결과값은 원래 비밀번호가 아니라 새로운 비밀번호 후보임.

---

# Hash Chain

Hash와 Reduction Function을 반복하여 하나의 체인을 만들 수 있음.

```text
P0
 ↓ Hash
H0
 ↓ R0
P1
 ↓ Hash
H1
 ↓ R1
P2
 ↓ Hash
H2
 ↓ R2
P3
```

각 기호의 의미는 다음과 같음.

```text
P : Password Candidate
H : Hash Value
R : Reduction Function
```

Rainbow Table에서는 체인 전체를 저장하지 않고 일반적으로 시작값과 끝값만 저장함.

```text
Start      End
P0   ----> P3
```

중간값은 필요할 때 시작값부터 다시 계산하면 복원할 수 있음.

```text
P0
 ↓ H
H0
 ↓ R0
P1
 ↓ H
H1
 ↓ R1
P2
 ↓ H
H2
 ↓ R2
P3
```

따라서 체인의 모든 중간값을 저장하는 것보다 저장 공간을 크게 줄일 수 있음.

---

# 기존 TMTO 방식의 충돌 문제

같은 Reduction Function을 계속 사용하는 경우 두 체인이 중간에서 충돌할 수 있음.

```text
A → B → C → D → E
X → Y → C → D → E
        ↑
      Collision
```

두 체인이 동일한 값 `C`에 도달하면 그 이후에도 같은 함수를 적용하기 때문에 결과가 계속 같아짐.

```text
C → D → E
```

즉 한 번 충돌하면 이후 체인이 완전히 합쳐짐.

이 경우 서로 다른 체인을 많이 만들어도 실제로 탐색되는 비밀번호 후보 공간이 중복되기 때문에 효율이 떨어짐.

---

# Rainbow Table의 특징

Rainbow Table에서는 충돌 이후 체인이 계속 합쳐지는 문제를 줄이기 위해 각 열마다 서로 다른 Reduction Function을 사용함.

```text
P0
 ↓ Hash
H0
 ↓ R0
P1
 ↓ Hash
H1
 ↓ R1
P2
 ↓ Hash
H2
 ↓ R2
P3
```

즉 체인의 위치에 따라

```text
R0
R1
R2
R3
...
```

처럼 다른 Reduction Function을 사용함.

실제로는 완전히 다른 함수를 여러 개 만드는 대신 열 번호를 같이 사용하여 결과를 다르게 만들 수 있음.

```text
R(hash, column)
```

따라서 같은 해시값이라도 적용되는 열이 다르면 Reduction 결과가 달라질 수 있음.

```text
R(hash, 0) ≠ R(hash, 1)
```

---

# Rainbow Table에서 비밀번호 찾기

공격자가 특정 해시값을 얻었다고 가정함.

```text
Target Hash
```

문제는 이 Target Hash가 체인의 어느 위치에 존재하는지 알 수 없다는 것임.

다음과 같은 체인이 있다고 가정함.

```text
P0 --H--> H0 --R0--> P1
P1 --H--> H1 --R1--> P2
P2 --H--> H2 --R2--> P3
```

공격자는 Target Hash가 어느 위치에 있는지 모르기 때문에 가능한 위치를 하나씩 가정함.

## Target Hash가 H2라고 가정

```text
Target Hash
    ↓ R2
    P3
```

계산된 `P3`가 Rainbow Table에 저장된 끝값과 같은지 확인함.

## Target Hash가 H1이라고 가정

```text
Target Hash
    ↓ R1
    P2
    ↓ Hash
    H2
    ↓ R2
    P3
```

다시 계산된 `P3`가 테이블의 끝값과 같은지 확인함.

## Target Hash가 H0라고 가정

```text
Target Hash
    ↓ R0
    P1
    ↓ Hash
    H1
    ↓ R1
    P2
    ↓ Hash
    H2
    ↓ R2
    P3
```

이러한 방식으로 Target Hash가 존재할 수 있는 모든 위치를 가정하여 끝값을 계산함.

계산된 끝값이 Rainbow Table에 존재하면 해당 체인의 시작값을 찾음.

그 후 해당 시작값부터 체인을 다시 생성함.

```text
P0
 ↓ Hash
H0
 ↓ R0
P1
 ↓ Hash
H1
 ↓ R1
P2
 ↓ Hash
H2
```

체인을 다시 계산하는 도중 Target Hash와 동일한 해시값을 발견하면 그 해시를 생성한 Password Candidate를 알 수 있음.

예를 들어:

```text
P2
 ↓ Hash
H2 = Target Hash
```

라면 `P2`가 해당 해시값을 생성한 비밀번호 후보임.

---

# Salt와 Rainbow Table

Rainbow Table의 장점은 미리 계산해둔 테이블을 여러 공격 대상에 재사용할 수 있다는 것임.

하지만 Salt를 사용하면 비밀번호 해시는 다음과 같이 계산됨.

```text
Hash(Password + Salt)
```

사용자마다 Salt가 다르면 동일한 비밀번호를 사용하더라도 해시값이 달라짐.

```text
Hash("1234" + Salt A)
        ≠
Hash("1234" + Salt B)
```

따라서 기존에 미리 계산해놓은 Rainbow Table을 그대로 재사용하기 어려워짐.

---

# 정리

- 암호화는 키를 이용하여 평문과 암호문을 변환함
- 해시는 임의의 입력을 고정된 길이의 해시값으로 변환함
- 해시는 복호화를 위한 연산이 존재하지 않음
- 해시값을 직접 역산하는 대신 비밀번호 후보를 해시하여 비교하는 공격이 가능함
- Salt는 비밀번호에 임의의 값을 추가하여 같은 비밀번호가 같은 해시값을 가지는 것을 방지함
- Rainbow Table은 Hash와 Reduction Function을 반복하여 Hash Chain을 만듦
- 체인의 시작값과 끝값만 저장하여 저장 공간을 절약함
- Reduction Function은 해시의 역함수가 아니라 해시값을 비밀번호 후보 공간으로 매핑하는 함수임
- 같은 Reduction Function을 반복하면 충돌 이후 체인이 계속 동일해지는 문제가 발생할 수 있음
- Rainbow Table에서는 각 열마다 다른 Reduction Function을 사용함
- 공격자는 Target Hash가 체인의 어느 위치에 있는지 모르기 때문에 가능한 위치를 하나씩 가정하여 끝값을 계산함
- 끝값이 일치하는 체인을 찾으면 시작값부터 체인을 다시 계산하여 Target Hash에 대응되는 비밀번호 후보를 찾음
- Salt를 사용하면 미리 계산된 Rainbow Table의 재사용이 어려워짐
